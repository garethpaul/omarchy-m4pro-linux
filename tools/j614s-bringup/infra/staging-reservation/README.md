# Explicit nonwriting allocator contract

**WORKS within offline scope:** exact resident allocator source, flat binary, paired ELF, symbol extents and raw-instruction evidence are bound by SHA256. Actual source host controls preserve every byte of the mock allocation arena across skipped spans; a deliberate writing variant fails. **PARTIAL:** a private geometry result can describe a separate child under this explicit contract. **UNTESTED:** live freshness, concurrency, reservation, staging, CPU readiness, recovery and hardware execution.

`reservation.py` has no filesystem, target, command or transport APIs. `plan_private(capture_bytes, expected_pins, *, binary_inputs, container_sha256, container_length, bootargs_bytes, bootargs_sha256, expected_raw_heap)` returns **private addresses**. Do not publish its result. It refuses absent binary inputs or any changed byte identity. `binary_inputs` must contain raw bytes under exactly five keys: `planner`, `source`, `flat`, `elf`, `instructions`. The constants in `PINS` identify the unchanged staging-plan helper, resident `heapblock.c`, resident flat/ELF and the frozen `allocator-instructions.json`. The helper is executed from hash-verified source bytes, without bytecode-cache loading. No target reader is imported.

The resident reports the8e0cf28 proxy version; the checked source checkout is `b3df851fb5f1d32bdff085b10049cb20e535c1a3`. This contract does not claim a whole-binary rebuild equivalence. The exact allocator instruction bytes, ELF function/global symbol locations and matching ELF/flat code sections independently bind the relevant behavior. The successful `heapblock_alloc` path aligns the raw heap to64bytes, computes `block+size`, checks an optional limit, and stores only the new `heap_base` (plus normal stack traffic). It does not initialize or dereference allocation memory. Error paths can call panic/assert machinery; the planner prechecks the relevant arithmetic and limits before describing a successful result. Source arithmetic itself lacks a general overflow guard: this API explicitly rejects overflow rather than attributing that protection to the resident.

`allocation_math` binds raw high-water, aligned return address, size, resulting high-water, usable end and optional allocator limit. `plan_private` protects the whole resident, live heap, live BootArgs/ADT, framebuffer and all applicable raw ADT ranges using the existing decoder. It searches for a2MiB-aligned64MiB child wholly clear of the merged protected union. The container must fit strictly below32MiB; its PIC entry is `child+0x800`; the final1152-byte BootArgs payload belongs at `child+32MiB`. The allocation size is **child_end − align64(raw_heap)**, so alignment padding cannot cause overshoot. The expected returned pointer and resulting high-water are recorded explicitly.

This explicit contract permits a high-water bookkeeping advance across reserved gaps. Those skipped gaps remain protected and unwritable; only the final clear child is described as a possible write destination. The resident bookkeeping variable itself is the one intended store, separate from child destinations. The previous strict whole-span refusal in `infra/staging-plan/` is untouched and remains the default. This API cannot authorize a write and makes no executable target commands. Root must separately review any stager and verify a fresh unchanged high-water immediately before using it, with exclusive allocator ownership.

Container SHA and length are facts supplied by an independently verified caller. This helper does **not** verify container bytes, CRCs, loader identity, DT, kernel or initramfs; it explicitly returns `CALLER_MUST_INDEPENDENTLY_VERIFY`. The supplied `bootargs_bytes` and hash identify the **original session BootArgs** and must match the pinned capture. They are not the final copied payload. The result proposes exactly one required field delta: `top_of_kernel_data` from the captured value to `child_end`. Root must construct the final1152-byte payload, verify that every other byte is unchanged, and separately bind its new hash. This API never constructs or verifies the final payload; it does not require that modified payload to retain the original hash. There is no actual verified container or real placement result in this checkpoint. CPU/WFE state is preserved in the result alongside unresolved gates; a geometry result is not an all-ready state. There are no firmware copies, ADT updates, RVBAR changes or future4GiB-allocation claims.

Host tests, from this repository root with the private workspace intermediates present:

```sh
python3 infra/staging-reservation/test_reservation.py
```

Five tests cover exact binary binding, absent/tampered proofs, layout/bounds and overflow failures, wholly synthetic clear-child geometry across a protected gap, unchanged strict-default refusal, and actual-source red/green controls. GCC and Clang each run63 unaligned allocator cases under fatal ASan/UBSan with warnings as errors. The entire mock arena and `heap_limit` remain unchanged. An intentionally injected `memset` variant fails the arena control under both compilers; this is a deliberate negative control, not a bug attributed to the original source. No actual capture is altered to produce a positive fixture. No target interface is opened, no allocator is called on the target, and no actual placement is emitted.
